# Windows glass UI

**Current default:** **Use existing** / **Track local usage**, not another login. **Account setup (only if needed)** exposes explicit recovery/add-account actions; Enterprise/personal billing remain separate advanced options. The Providers section of the unified settings area has a collapsed native source-capability inventory and independent history controls. Earlier login-first descriptions below are superseded by [SOURCE-ARCHITECTURE.md](SOURCE-ARCHITECTURE.md).

The user's Windows Search screenshot is the material/chrome reference: native frosted acrylic, softly rounded corners, Segoe UI, restrained monochrome controls, translucent tiles and fine separators. The earlier usage screenshot supplies the quota/remaining-bar layout, not desktop/menu-bar decorations.

## Navigation — 2026-10-20

- The main provider grid contains quota/account cards, not the token-summary and spending block.
- The header's **Usage** pie-chart button opens a separate page with **All providers** or an explicit provider filter, Today/Last 30 days counters, period controls, donut, legend, credit observations and report copying. Its scope is independent from the selected quota tab. Missing history remains unavailable; a quota connection does not imply recorded tokens. Pricing links open the existing model-rate editor without saving the draft.
- One **Settings** gear opens **Providers & settings**: the **Providers** section manages monitored scopes, source/history controls and connections; **App settings** contains appearance, discovery, refresh, pricing and other preferences. Both share the same canonical settings/draft. Add and provider-title shortcuts open Providers with the selected provider.
- Page/section navigation does not start authentication, change saved preferences or interrupt hidden background tracking. Native tray, pin, docking and motion behavior are unchanged.

## Native window

- Tauri creates a transparent, frameless WebView with Windows acrylic enabled. On Windows 11, DWM uses `DWMSBT_TRANSIENTWINDOW` and native rounded-corner clipping. Older supported Windows versions use the native acrylic fallback. This is not a CSS imitation of desktop blur.
- Account-header logos are standalone marks with no square background, border or shadow in either theme; identity headers retain the six-dot reorder handle on the left and bare provider mark on the right. A generic single-account heading is omitted when it would only repeat the provider title; verified emails/nicknames remain visible.
- HTML/body backgrounds are transparent in the desktop app. The panel has no dark strip or padded side gutters. Its small header is an ordinary translucent app heading with refresh/pin/usage/settings/collapse controls, not a simulated OS status bar.
- Light/dark/system preferences update both the WebView and native window theme. Windows owns material availability/accessibility fallback. Browser-only design previews use a pale background because a browser cannot apply DWM to its containing window.
- Default placement is **bottom-right**, above the taskbar; bottom-left and clicked-icon docking are explicit preferences. The tray flyout is fixed-size, with internal scrolling rather than a resize frame.

The header pin sits immediately after refresh. It toggles native **always-on-top**, with pressed/filled styling, accessible action labels and keyboard activation. `dashboardPinned` persists across restarts; its default is **false**. New profiles and older profiles without this field start unpinned. An explicitly saved pin/unpin choice is retained, not reset by an upgrade. The targeted save merges only that preference without quota reads or overwriting unsaved form edits. Failed writes restore both the native state and pressed state. Unpinned is the default: clicking another app or the desktop dismisses the panel after a short 120 ms grace period. Pinning explicitly keeps it open on focus changes and always on top. DOM/input blur inside the panel does not dismiss it. Refocus and explicit reopening cancel stale dismissal timers. Owned popups and a guarded native folder picker keep their parent visible. Tray activation is one icon-matched press/release gesture: it snapshots the presented popup, including an in-flight blur-close, rather than its already-hidden target. Windows' DoubleClick notification is treated as the second press (it replaces a normal mouse-down). A late release therefore keeps the popup closed; unmatched, duplicate, cross-badge and expired releases never become new open requests. The two-second press lease cannot suppress dismissal forever. Context-menu Show usage remains explicit; tray clicks do not raise the parent over an active folder picker.

The former X is a **down-chevron** labelled Collapse dashboard. It hides the flyout, not the app, and never clears the pin preference. Explicit collapse, Escape and tray-click hiding remain available while pinned; background tracking continues.

## Flyout motion

The **entire native popup** rises from its bottom dock edge over **300 ms** and rolls back down over **220 ms** on collapse, Escape, tray dismissal or unpinned focus loss. This is a full-panel reveal, not the former nearly invisible 10px nudge or content moving inside a stationary glass box. The native glass, rounded boundary, shadow and header travel together; the existing fade is retained. Both directions respond on the first frame and decelerate to rest; the previous flat-start curve made the popup appear reluctant to move. The dock-side edge stays fixed throughout, without an additional positional nudge. Short reversals settle in a distance-scaled 80–300 ms rather than restarting the entire glide. A top-edge tray anchor reverses the direction. The dock-side edge remains within the monitor work area; final window size and coordinates are restored exactly.

Frame updates follow compositor wakes on a short-lived worker, without blocking the UI thread or adding a coarse sleep after each frame. Progress is sampled at actual UI execution time; duplicate geometry/opacity and unchanged native viewport bounds avoid redundant work. There are no animation workers/timer callbacks running at idle and no global timer-resolution changes.

Motion is owned by Rust, not a DOM blur handler or CSS-only content effect: the actual HWND changes its top/visible height, while WebView2's full viewport stays fixed. No content resizing, reflow, scroll changes or CSS transforms are introduced. A temporary own-window resize guard is removed after restoring the full host, then normal sizing is resynchronized. While native opacity is leased, that same owned-window guard preserves only `WS_EX_LAYERED` across framework show/pin style rebuilds; otherwise an alpha-zero popup could flash opaque and fade back in. Pin/focus flags are never overridden by this guard. Uniform native HWND opacity includes the glass and WebView; temporary opacity styles are restored after completion. New gestures reverse from the current position/opacity, and sequence guards prevent an old close from hiding a reopened panel. The first reveal waits for mounted UI, with a bounded readiness fallback. WebView focus is restored only if the panel still owns native foreground focus, never stealing it back from another app or a folder dialog.

Windows Accessibility **Animation effects** is read for each transition, never changed; disabled animation or a remote session uses instant show/hide. No animation timers run while idle/hidden, and tracking continues independently.

## Grok sign-in and renewal — 2026-10-23

Explicit **Sign in with Grok** uses the official CLI's device-code flow: enter the terminal's code on the official website and keep the terminal open. No code input is added to the WebView. **Browser return-code help** explains pasting a full return URL into the titled **OpenToken - Grok sign-in** terminal, with an explicit browser-mode alternative. **Enable automatic Grok renewal…** opens an owned default-No native review for repeated owner-side `models` commands after authentication rejection. It is separate from sign-in, read-only reuse and one-shot recovery. The saved connection/details identify approved renewal; disconnect or successful read-only reuse removes that permission. No production renewal or login completion is implied by a passing fixture or a dismissed review. See [the investigation and limits](GROK-SESSION-2026-10-23.md).

## Monitoring health

Saved sources remain listed during read failures. The panel explicitly distinguishes **Monitoring saved · cached usage**, **usage unavailable**, and **sign-in needs recovery**. A temporary failure keeps its last same-scope reading labelled cached/not live and explains automatic retry; a cold temporary failure does not display a reconnect form. Real login, permission or identity problems expose explicit setup and never reuse untrusted quota. Current mini-stripes remain suppressed while stale; native tray registrations are retained with cached/error styling. Source failures are not labelled as user-initiated disconnects.

## Live tracking feedback

The existing glass layout and provider order are unchanged. A quiet footer indicator distinguishes watching, recent CLI activity, periodic fallback, off, initialization and index errors; demo data never masquerades as a live connection. Native background events push token/value totals while the flyout is hidden. Opening it refreshes the local snapshot, not the provider quota API.

Tray badges and the tiny provider stripes follow the same revisioned quota snapshots as the cards. Tooltips and Usage details distinguish provider verification, identity-matched provisional CLI hints, cached values and unavailable readings. Anonymous log percentages never move an account's badge. While active, verified checks normally run once a minute, subject to provider backoff; idle interval and Live tracking are configurable. See [live tracking](USAGE.md#live-tracking).

Visible observation ages/countdowns tick every five seconds (including seconds in the final reset minute). Hidden windows stop those display timers; elapsed time never restores a quota on its own. Reduced-motion settings suppress the subtle activity pulse.

## Native tray

The default is **one Fluent percentage badge per identity**, restoring the earlier glanceable single-number design. Its 64px artwork uses antialiased circular geometry, rounded progress caps, an understated Azure/slate surface and the locally installed Segoe UI font. Blue is the normal accent; amber signals low remaining quota, red signals a failed read, and gray distinguishes cached/unknown values. The number and arc both mean quota remaining. GDI bitmaps, fonts, selections and memory DCs are RAII-scoped; no font files or external rendering dependencies are bundled.

**Settings → App settings → Tray icon style** retains the optional provider-logo/stacked-percentage pair. Windows reserves a square slot for each icon, so that optional macOS-like layout needs two actual Windows icons. Automatic mode stacks session above weekly; explicit session/weekly modes show only that metric.

Both styles toggle the same dashboard and expose its native context menu. Icons adapt to the Windows taskbar theme independently of the app theme. Windows controls spacing, order and overflow visibility. Changing styles immediately reconciles native resources; removing an identity unregisters every owned icon. No Explorer injection, fake taskbar or extra supervisor is used.

## Truthful data

- `/v1/state` percentages remain **used quota**. UI/tray convert to `round(clamp(100 - used, 0, 100))` and label them **left**.
- The full spending functionality is on the separate **Usage** page: periods, donut and provider legend. Rust indexes local Codex/Claude records, including subscription usage, to calculate token totals and reference-priced API-equivalent value. The ring explicitly says **estimate**, never subscription charges. Partly priced totals show a `≥` dollar lower bound and unpriced-token explanation; entirely unpriced usage falls back to a token-count ring; missing records remain dashes, never fabricated zero-dollar amounts. Indexing progress and incomplete records are disclosed. Settings exposes reference rates and explicit overrides. Observed credit changes are a separate collapsed disclosure, not billed spend. See [usage tracking](USAGE.md).
- Usage details are collapsed by default in both live and demo views. Credits and reset allowances stay inside that disclosure, beneath quota bars, with linked expanded/hidden accessibility state. Historical cost estimates are provider-level: local records do not reliably identify which account was signed in at the time.
- Six-dot handles reorder the selected provider’s identity cards vertically using the mouse/touch or Space/Enter → Up/Down → Space/Enter. Escape cancels a move without hiding the panel. Stable identity-keyed order persists in settings; failed writes roll back. New accounts append, missing identities retain their remembered preference. Single-account handles explain that another account is needed. Windows still controls tray-icon order.
- `?demo` is visibly labelled sample data. Example spending, token totals and forecast ticks never enter native caches, account discovery or the API.
- The demo period selector is functional. The share control copies a credential-free/folder-free usage report. Account details genuinely expand/collapse.

Components are in `src/components`, pages in `src/pages`, and formatting in `src/format.ts`. Provider vectors and generated native marks are bundled locally; see [third-party notices](THIRD-PARTY.md).
