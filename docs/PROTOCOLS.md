# Provider protocol notes

## Codex

Locate an actual `codex.exe` on PATH or known npm vendor paths (no command-shell interpolation). Spawn a short-lived `codex app-server --listen stdio://` under an isolated CODEX_HOME. Remove CODEX_API_KEY, CODEX_ACCESS_TOKEN, OPENAI_API_KEY and CODEX_SQLITE_HOME. No console flash; kill-on-drop plus explicit kill/wait; overall 25s timeout; stdout LinesCodec limit 2 MiB; stderr discarded, not logged.

JSON-RPC sequence:

1. initialize { clientInfo: { name: opentoken, version: 1.0.0 }, capabilities: { experimentalApi: true } }
2. initialized notification
3. account/read { refreshToken: false }
4. account/rateLimits/read {}
5. account/read { refreshToken: false } for a post-read identity check

Ignore unsolicited notifications; numeric IDs correlate responses. Require chatgpt account type. Compare email/accountId/id before and after. Prefer returned workspace ID; otherwise use a home-scoped opaque key for credential-store discovery.

CLI payloads (`rateLimitsByLimitId`, fallback `rateLimits`) and HTTP snake_case payloads map directly to domain quotas, not via JSON serialization round-trips. Classify 18000s as Session and 604800s as Weekly regardless of primary/secondary slot. Preserve daily/monthly/annual/custom windows; Spark is a separate bucket. Credits/reset counts are typed values. The displayed $0.04/credit estimate follows QuotaTray; it is not a pricing guarantee.

File-only fallback GETs https://chatgpt.com/backend-api/wham/usage and best-effort /rate-limit-reset-credits with Bearer token and ChatGPT-Account-Id. Identity is re-read from the file before/after and compared with returned account/email fields when present. No refresh-token grant is issued. Keyring/auto stores do not use fallback files; malformed config files fail closed.

## Native CLI sign-in setup

Typed `start_cli_sign_in(provider: codex|claude, consent: true)` starts one bounded native run per provider; cached `get_cli_login_status` reads in-memory progress only, and `cancel_cli_sign_in` stops checking/waiting. The frontend supplies no account path, CLI arguments, executable, OAuth client or callback URL. The app allocates/reuses a pending opaque profile and invokes `codex login` with isolated CODEX_HOME, or `claude auth login --claudeai` with isolated CLAUDE_CONFIG_DIR. Native executable launch uses no command shell/installer and clears API-token/endpoint override variables. The official CLI console/browser owns authentication; output is not captured. File metadata and successful child exit only signal readiness (including keyring-only Codex); the existing adapter must authenticate and verify available usage before engine persistence/publication. Claude connection verification does not renew tokens.

`CliConnect` and `CliDisconnect` serialize account settings against latest engine state. A failed save cannot publish success; pending credentials remain provider-owned for a later retry. Disconnect excludes all known identity sources without credential deletion. Generic saves preserve newly connected sources/enabling and disconnect exclusions against older drafts. Revisioned `cli-login-changed` and targeted `cli-accounts-changed` metadata events continue across navigation/hiding and merge only relevant settings. The old arbitrary-home `login_codex` command and folder setup UI are no longer used. Legacy configured homes, discovery, history sources and optional Claude renewal remain compatible. Waiting is two minutes; verification spacing/hourly/provider pauses remain enforced. See [connection setup and limitations](CONNECTIONS.md).

## Personal Cursor desktop session (unofficial dashboard)

With explicit user consent, read only `cursorAuth/accessToken` from the standard Windows Cursor `state.vscdb`. Use read-only SQLite, live-WAL handling, bounded value/busy/progress limits and no database copy; no token refresh or browser-cookie import. Reject malformed/near-expiry JWTs and require provider-authenticated stable identity via fixed `https://cursor.com/api/auth/me` before and after `GET /api/usage-summary`, with a final local token reread. The session cookie derived in Rust is `WorkosCursorSessionToken=<subject>%3A%3A<accessToken>` and never enters IPC, settings, snapshots or logs. These are undocumented endpoints, not public Enterprise API access or a third-party OAuth contract.

Only finite reported `individualUsage.plan.totalPercentUsed`, `autoPercentUsed` and `apiPercentUsed` map to monthly/Auto/API windows; actual billing dates supply resets. No missing quota, unlimited percentage, cost, token count or team-to-individual assignment is inferred. Personal reports serialize `source: cursor_dashboard`; provider raw percentages stay used and UI stays left. A local account switch invalidates prior readings and requires explicit reconnecting, never silent account replacement. Native `start_cursor_sign_in` consent starts a bounded coordinator, `get_cursor_login_status` returns cached progress only, and `cancel_cursor_sign_in` cancels read-only checking/waiting. Private engine marker probes never reach IPC events or logs; final `connect_cursor_personal` verification and profile/mode-scoped metadata remain separate from Enterprise API keys; disconnect removes monitoring only. The optional CLI and external-browser cookie-import routes were researched but are not implemented in this version. See [connection setup](CONNECTIONS.md).

## Cursor Enterprise and personal Copilot billing

Official API sources and exact capability boundaries are documented in [CONNECTIONS.md](CONNECTIONS.md). Cursor uses Basic-authenticated `GET https://api.cursor.com/teams/members` and read-only `POST /teams/spend`, binding both exact email and verified member ID to a credential-key scope. Only a positive provider-supplied enforced on-demand limit supplies a percentage; no personal/included subscription limit or reset is inferred. Fractional cents are retained until display.

Copilot uses a user Plan-read fine-grained token for `GET https://api.github.com/user`, personal `/users/{verified-login}/settings/billing/{premium_request|ai_credit}/usage?year=…&month=…`, then `/user` again. Numeric identity and returned login/period/unit checks reject cross-account readings. Only Copilot product rows are included; premium requests, AI credits and their net usage amounts remain separate, and empty reports do not establish zero usage. A missing individual report can be unavailable, but lack of access to both is an error. Organization-paid usage, remaining allowance denominators, local tokens and invoices are not synthesized.

`Provider` and API `/v1/usage/{provider}` filtering now include `cursor` and `copilot`; API keys are never exposed through HTTP; snapshots contain only the public account/identity/scope and usage fields. Native `connect_provider` and `disconnect_provider` serialize verified configuration changes through the engine. Only an allowlisted provider/help selection can launch an external browser page. Fixed HTTPS hosts, no redirects, 2 MiB bodies, bounded Cursor pagination, whole-operation deadlines, provider pauses and connection-attempt budgets apply. No browser-session extraction or substitute OAuth client IDs are used.

## Expanded credential-scoped usage

Z.ai Coding Plan: fixed `api.z.ai` or `open.bigmodel.cn` quota-limit endpoint, explicit region and bearer key; recognized token/credit/MCP limits only. Kimi Code: fixed selected regional `/coding/v1/usages`, ratio pools (`limit_5h`, `limit_7d`, `limit_month_total`) plus supplied legacy counters, with matching resets preventing duplicate/incorrect overlays. DeepSeek: official `/user/balance`, separate total/granted/paid and currencies, never a percent-left. OpenCode Go: `/zen/go/v1/usage`, rolling/weekly/monthly **percentage units**, so `1` is 1%. Fixed hosts, bounded/redirect-disabled JSON and sanitized errors are shared. Keys are scopes, not guessed people. Native scheduling/storage/tray/API filters support all four; local-history attribution is unchanged.

Copilot's default `github_cli` mode delegates browser authorization to the installed official gh client and reads its credential only after consent/persisted monitoring. It verifies `/user`, uses sensitive `Authorization: token ...` for `/copilot_internal/user`, verifies identity again and compares the final local token. No copied VS Code client ID or editor-identity spoofing is used. Only supplied metered quota/reset fields are published; unlimited/zero-entitlement placeholders are omitted, and credits have no fabricated ceiling. This unofficial entitlement source serializes `copilot_internal`, distinct from advanced official personal billing. Disconnect never deletes/revokes the gh token. The engine wraps verification in its deadline and connection/pause gates.

Windows login children now use CreateProcessW without inherited standard handles and with a real new console. The old GUI release was measured with three nonterminal streams; the new console probe and native smoke check all three streams. Fixed CLI commands, sanitized auth environment, owned process handles and 10-minute MFA waiting replace an output-only synthetic readiness assumption. Full evidence and provider-specific boundaries: [PROVIDER-RESEARCH.md](PROVIDER-RESEARCH.md). Antigravity/Devin/Muse native paths are detailed below.

## Antigravity, Devin and Muse native sources

Current installed-version correction: [COMPATIBILITY-2026-10-19.md](COMPATIBILITY-2026-10-19.md). Antigravity checks both app/IDE profiles and also supports an explicitly allowed saved agy bearer, with acceptance decided by the provider rather than cached expiry from exactly `gemini:antigravity`, Google userinfo before/after, daily Cloud Code quota and exact entry recheck (`antigravity_cli`); no token renewal or production-Gemini merge. Devin additionally reads only the standard desktop `windsurfAuthStatus` authentication record with bounded read-only WAL handling and deployment/context checks (`devin_app`). Cursor accepts a canonical OIDC subject without treating auxiliary numeric database IDs as account mismatches. Deliberate native diagnosis persists no connection and exposes no credential/identity getter. The newer `antigravity_stored` mode decodes the exact IDE USS topic, validates its fixed daily deployment and active non-GCP tier through `loadCodeAssist` context lookup, and never calls onboarding/production quota. [Explicit owner recovery](SESSION-RECOVERY-2026-10-19.md) is separate: installed GUI or `agy models`/`grok models`; new Grok OAuth uses only the separately chosen `grok login --oauth`. Successful process exit still requires authenticated quota verification.

- **Antigravity:** current-user standard Windows desktop language-server process/lifetime/port/CSRF validation; fixed loopback Connect RPC `exa.language_server_pb.LanguageServerService/GetUserStatus` around `RetrieveUserQuotaSummary`. Shared bucket IDs `gemini-5h`, `gemini-weekly`, `3p-5h`, `3p-weekly` map explicit `remainingFraction` to raw used percent; missing/disabled/unknown/ambiguous buckets do not manufacture limits. Unsupported summary builds can use explicit legacy per-model quota, not invented weekly windows. No scripts, arbitrary local scanning, proxy/redirect forwarding or borrowed Google renewal. `antigravity_local` provenance.
- **Devin:** known Windows CLI TOML `windsurf_api_key`, fixed `https://server.codeium.com/exa.seat_management_pb.SeatManagementService/GetUserStatus`, JSON Connect protocol v1 with key native-only in metadata. Product context `ideName=devin`; caller extension/User-Agent OpenToken and unknown IDE version, not a fake installed client. Require Devin entitlement and stable local credential/server context. Explicit percent remaining is converted to used; hidden daily data with ambiguous weekly meaning stays raw/unmapped, reset-only omissions unknown. Overage micros are separate USD value. `devin_cli` provenance and credential/context-bound metadata.
- **Muse MSP:** installed native `muse serve`, bounded JSON lines/12-second probe, lowercase honest client identification, initialization plus `usage/read` only (or actual `usage/changed`). Optional usage is truthful absence, never zero; actual `observedAtMs`, tier, supplied window duration/used percentages/reset stamps are retained. A fresh host may have no observation from existing terminals. No session/turn/auth/payment/mint request. `muse_cli` provenance; no universal keyring import.
- **Muse explicitly allowed key mode:** separate `connect_muse_subscription` requires a default-No native warning before any credential/endpoint work. `POST https://api.meta.ai/muse-code/key` with existing CLI device credential and `x-api-version: 1.0.0` can issue/rotate an inference key; the UI discloses unknown replacement effects and repeated background access until disconnected. Only real authenticated email and supplied `subs_usage.{window,weekly}` percentages/reset data are returned; inference keys are discarded and never used/stored/written back. No automatic fallback or foreign OAuth registration. `muse_device` mode/source; recovery backups omit this grant. Cancelling/failing save cannot undo an already-sent request.

All paths share native scheduling, deadlines, bounded HTTP responses, secret-free models, scope-change rejection, canonical connection persistence and monitoring-only disconnect. The default source operation is cancellable; already-issued provider side effects are not reversible. ## Local activity, provenance and native push

`event_msg` with `payload.type=token_count` may carry snake-case `rate_limits.primary/secondary {used_percent, window_minutes, resets_at}`. The live parser accepts finite 0–100 usage and known 300/10080-minute windows, and rejects unrelated limit IDs. Counts remain separately deduplicated. Only metadata fields are decoded; transcript strings are never interpreted as protocol events.

Normal Codex rollouts lack sufficient account proof. Those records and Claude usage revisions only signal an authenticated refresh for accounts whose current configured sources match that home. An optional explicit `payload.account {workspace,email,user}` can enable a direct provisional update, but only with an exact current identity match, file-backed auth consistency before/after, ready status, newer/recent observation, matching advertised reset and nondecreasing usage. Neither a folder nor auth-file mtime substitutes for that proof. Startup/history replay cannot replace newer verification. The implementation does not claim current Codex CLI versions normally emit this explicit proof.

Reports add `source: provider|cli_log` and `verifiedAt`. `observedAt` is the latest accepted observation; `verifiedAt` is the last provider check (old caches fall back to their observation time). CLI updates only replace matching quota windows, not balances or plans. A transient read failure retains stale data; local hints cannot mask it. A provider confirmation returns the report to `provider` source.

Native `spending-changed` carries a revisioned `TrackingState` with cached aggregate spending, watcher mode/error and provider-level activity timestamps; it contains no paths or credentials. `get_tracking` and compatibility `get_spending` read cached state only. `state-changed` still drives quota cards, mini stripes and native badge reconciliation. Automatic active reads are spaced by 60 seconds; idle interval, reset deadlines, per-run rolling hourly budget and Retry-After govern scheduling. Manual clicks have a two-second burst guard and cannot bypass a server throttle.

## Claude

Read claudeAiOauth from CLAUDE_CONFIG_DIR/.credentials.json or ~/.claude/.credentials.json, or explicitly configured homes. Require user:profile when scopes are recorded. GET https://api.anthropic.com/api/oauth/usage with anthropic-beta oauth-2025-04-20 and the existing QuotaTray-compatible Claude Code user agent.

Renew within 5 minutes of recorded expiry (or once after 401), if permitted, using https://platform.claude.com/v1/oauth/token and the provider client ID inherited from the old behavior. Acquire OpenToken's advisory lock before re-reading, compare current credentials before writing, preserve unrelated JSON fields, and atomically replace. See SECURITY.md for unavoidable cross-application races.

Map five_hour, seven_day, seven_day_sonnet, seven_day_opus, generic weekly_scoped model limits and extra_usage. Extra usage values are cents → USD; plans use Claude subscription names, not Codex Pro price-tier aliases. 429 supports numeric Retry-After seconds.
