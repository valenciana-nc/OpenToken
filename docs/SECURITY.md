# Security and operational limits

**Source-first migration:** discovery reads known-source metadata only; existing-session connection cannot launch login or prepare managed profiles. Local Grok/Kimi/Muse records need no credentials. History choices are independent of quota auth; a changed credential scope cannot inherit cached quota or bypass original throttle. New Claude profiles default legacy renewal off; saved choices survive. See [SOURCE-ARCHITECTURE.md](SOURCE-ARCHITECTURE.md) for exact scopes and unfinished readers.

## Antigravity, Devin and Muse source boundaries

The new original Rust readers remain native/permissioned. Antigravity uses narrowly filtered same-user Windows process/SID/session/executable/lifetime metadata and PID-owned listening ports; it does not spawn PowerShell/netstat, read process memory or scan arbitrary local services. CSRF stays native, account email and ownership are confirmed around the quota RPC, redirects/proxies are disabled, and self-signed TLS exceptions are confined to constructed verified loopback URLs. Standard install-path evidence is not cryptographic binary attestation or a defense against hostile software already running as the same user. Ambiguous instances/custom installs fail rather than choose another account.

Devin reads the selected official CLI TOML, or the standard Devin desktop's exact `windsurfAuthStatus` SQLite record when no CLI file exists, safely and read-only. Desktop JSONC deployment overrides and the login-selected server in `codeium.windsurf` state are checked before/after; a custom tenant is rejected before credential forwarding. No database copy, checkpoint or new sidecar is used. Both modes pin the remote HTTPS server. It does not harvest browser storage, accept an arbitrary endpoint, invent an IDE version, reuse a foreign OAuth registration or infer weekly quota from hidden daily fields. Local credential/server changes reject cross-scope readings. Its scope is explicitly credential-bound when no independently authenticated human identity is available.

The separate `antigravity_cli_usage` mode is explicitly approved via an owned default-No native confirmation, not an existing-source fallback. It runs only the installed version-gated official CLI's `/usage` command with zero-turn/zero-model-token validation, bounded native pipes/deadlines and no raw reply export. It follows the current CLI profile (including account switches) and is labelled as such, not a verified human; it never assigns a selected account or anonymous history. The official client may renew its own login during approved background reads. No borrowed registration, credential copy or prompt is supplied. Old profile reports are discarded on restart/failure and expired without rollover; recovery backups omit this grant. See [repository comparisons and implementation](ANTIGRAVITY-RESEARCH-2026-10-19.md).

Antigravity additionally supports deliberate agy CLI reuse through exactly the vendor-owned `gemini:antigravity` Windows entry: read-only, bounded UTF-8/UTF-16/base64 decoding, structurally valid bearer with provider-authoritative acceptance, fixed Google userinfo before/after daily-host quota and final entry comparison. No foreign credential is copied into OpenToken's vault; no grant is renewed or vendor registration borrowed. Production Gemini is a different quota pool and is never merged. Saved desktop connections do not silently switch to CLI after a failure. Isolated source homes are barred from reading the real vendor vault.

Muse default MSP probing invokes only the installed native executable and initialization/usage-read messages, with bounded pipes/time/output and owned-child cleanup. It sends no agent prompt, session creation/resume, auth, payment or mint request. A fresh host without an observation is unavailable. The inline CLI credential is used to bind source scope; no token reaches the WebView/vault. Expired observations are removed without reset extrapolation. Watch registration precedes credential checks, closing a real check/watch race; credential changes clear cached readings while preserving read spacing.

**Muse advanced key endpoint is an explicit exception to read-only monitoring.** A separate native confirmation defaults to No (Escape/Cancel also decline) and warns that Meta can issue/rotate a CLI inference key, replacement effects are undocumented, running sessions may be affected, and saved-mode background refresh repeats the request until disconnected. No read occurs before confirmation; default MSP/local history never silently selects this mode. Only a verified quota plus authenticated email is persisted. Returned inference keys are discarded and never used/stored in the vault, exported or written into Muse; response buffers/private strings clear where owned, without claiming HTTP/OS transient copies are impossible. Cancellation, network failure or save rollback cannot undo a request already sent. Automatic settings backups omit `muse_device` grants so corruption recovery does not silently resurrect credential issuance after disconnect. Primary settings retain a deliberately approved mode across normal restart.

Regression validation remains synthetic: API fixtures are loopback, CLI/desktop processes are owned synthetic children, and the actual native consent test declines the dialog. Separately, deliberately allowed real-source diagnosis inside the native executable verified Cursor/Devin usage. Later fixed-provider requests confirmed Antigravity IDE/Grok rejection; Claude's selected record has no usable access token. No diagnosis renews credentials. No new OAuth, model call or Meta key issuance occurred. The explicit `--diagnose-existing <provider> --allow-existing-source-read` path runs before logging/settings/startup/instance initialization, persists no connection, exports no identity/token and cannot invoke the Muse key mode. See [the compatibility investigation](COMPATIBILITY-2026-10-19.md). See [CONNECTIONS.md](CONNECTIONS.md) and [the source/recovery correction](SESSION-RECOVERY-2026-10-19.md) for exact modes and limits. The distinct `antigravity_stored` reader validates the exact IDE topic, deployment and active tier before daily-only quota; it never substitutes production/GCP quota or calls onboarding. Explicit recovery delegates to the selected installed GUI or model-list CLI command, separately from read-only reuse. Grok new OAuth setup uses `login --oauth` and is never an automatic model-check fallback.

## Credential boundary

Only the provider modules read existing CLI tokens or explicitly consented Cursor desktop tokens. App-owned API keys are submitted through local native IPC, verified against fixed official endpoints and stored in Windows Credential Manager; no credential getter exists. Token-bearing structs are not serializable frontend/API types, and raw HTTP response errors/bodies and CLI stderr are never logged. No authentication files are imported or copied into OpenToken data. Codex overriding token environment variables are stripped from helper children. Production requests use fixed HTTPS hosts with redirects disabled. Providers have bounded JSON bodies; CLI line length is bounded before parsing.

Codex identity checks are consistency checks of local claims, CLI identity and any returned HTTP identity. JWT signatures are not verified locally. An authenticated provider request supplies authenticity of access; a hostile process already running as the same Windows user is outside the protection boundary.

Claude advisory locks coordinate OpenToken processes only. Re-read/compare/patch minimizes overwrite risk but cannot make an HTTP token rotation and another app's credential changes transactional. A conflict produces a relogin error rather than overwriting. Atomic writes use inherited directory access controls; keep CLI credential folders private to your Windows account. The lock file contains no credentials. Read-only renewal mode is available.

## Personal Cursor desktop monitoring

Personal mode is opt-in: rendering its form or starting without a persisted personal connection does not open Cursor's sign-in database. The native start/connect commands reject missing consent before any credential lookup. The single sign-in action requests read-only access, described by the button tooltip and associated accessible description (the former bottom caption/info row is removed); cached status queries read only in-memory progress. Rust reads only `cursorAuth/accessToken` from the standard Windows Cursor profile using bounded SQLite read-only access off the UI thread, with no whole-database/browser copy, recursive credential discovery or token persistence in OpenToken's vault. Working bytes/tokens are zeroized where owned. Live WAL state is respected; missing sidecar pairs, active rollback journals, linked sources and oversized/invalid rows fail closed. Immutable access is used only when no WAL/SHM exists, with post-read checks; SQLite's normal shared-memory coordination is not a credential write.

The app never renews or deletes Cursor's tokens. JWT subject/expiry checks do not verify signatures: fixed-host provider requests authenticate the session, and account identity is verified before/after usage with a final local-session reread. Account changes invalidate old readings and cannot silently turn into a different connected identity. A fingerprinted native watcher filters unchanged tokens and retains normal read budgets/backoff. Personal metadata is mode/profile scoped; legacy API metadata defaults to the old mode, and general preference commands cannot forge or erase the connection list. Disconnecting a personal connection removes only monitoring metadata and never touches the vault or Cursor files. Only actually reported quota fields are exposed; missing/unlimited/team data is not an individual allowance. The dashboard endpoint is explicitly unofficial/unstable.

Opening Cursor to sign in launches an existing `Cursor.exe` from fixed standard install roots, without a shell, arbitrary PATH lookup, remote installer, embedded password form or fake OAuth client. Custom installs may be opened manually. No CLI-only credential transport or browser-cookie import is claimed. See [setup and capability limits](CONNECTIONS.md).

## CLI account setup

An explicit one-button Codex/Claude action allocates/reuses one app-managed pending home, then invokes only the installed native official CLI with fixed subscription-login arguments. No arbitrary executable/path/URL comes from IPC. The new home is separate from existing CLI homes; it is not a copy or sign-out. Pending files and directories reject linked/reparse paths, oversized metadata and malformed IDs. Login children receive an isolated home and stripped API-token/alternate-endpoint overrides; their console/browser belongs to the official CLI. Output, passwords and tokens are never captured by this coordinator. Readiness is private file metadata/exit status, not identity proof: the engine adapter verifies subscription usage before saving preferences/publishing. Claude connect verification uses renewal off; ordinary optional renewal stays unchanged. Cached status reads are in-memory only.

Each CLI provider has one active epoch/revision-guarded run with a ten-minute waiting limit for MFA/SSO. Cancellation stops read-only waiting and terminates only its owned CLI child; it does not close browsers, revoke sessions or delete provider credentials. Verification already handed to the engine may commit. Retry reuses an uncommitted pending home, while a later new-account action never overwrites a committed one. Managed directories inherit the current user's ACLs; they contain provider-owned credentials, are not encrypted by OpenToken and remain after monitoring-only disconnect/uninstall. Existing CLI homes, QuotaTray credentials and startup entries are untouched. Source settings/metadata are not secrets and retain the existing cache/backup disclosure. Generic settings preserve newly added managed homes; targeted events merge only relevant account fields, not unrelated drafts. The manual-folder UI and arbitrary-home legacy login command were removed, not legacy account support. See [connection setup](CONNECTIONS.md).

## Native sign-in coordination

`cursor_login` holds a single epoch/revision-guarded run. Local probing starts only after an explicit sign-in action, stays off the WebView thread, is bounded to a two-minute waiting window, and exposes no private credential marker. Existing local sign-ins are verified directly; otherwise the fixed native launcher opens Cursor once, then the coordinator waits for a usable/changed session. An unchanged rejected session is not repeatedly sent to the provider. Verification attempts retain spacing, hourly budgets and backoff; failures do not become connected status. Checking/waiting may be cancelled; write-capable verification is allowed to finish. Disconnect resets progress and invalidates stale workers after the serialized engine transaction. Closing/hiding/navigation does not invent a completed login or move credentials into frontend state. Canonical connection-change events merge only public metadata into saved/draft settings.

## Expanded API scopes and GitHub CLI delegation

The new Z.ai/Kimi Code/OpenCode Go/DeepSeek adapters send explicitly entered API keys only to fixed selected-region HTTPS endpoints. They use the app-owned vault and existing verification/persistence rollback. The public account is an API-key scope, not a guessed person/email. Region and key fingerprints prevent mixing cached readings. No missing/unlimited allowance is invented; balances and quota remain outside token-history/invoice accounting.

Grok's `grok_cli` mode is also explicitly opt-in. Cached status has no credential I/O. Bounded read-only access to the known official CLI auth profile refuses linked/team/ambiguous sessions; cached expiry alone does not establish rejection; refresh-token fields are ignored and the official CLI owns renewal. Authenticated xAI userinfo before/after private billing plus a final exact local-token comparison reject identity/session switches. Only public metadata is persisted; the token never enters OpenToken's vault, settings, cache or WebView. Disconnect leaves the provider profile untouched. No management-key inference request, borrowed OAuth client or browser-cookie import is used.

Copilot's new `github_cli` mode is opt-in. Cached status reads inspect no credentials; an explicit sign-in or persisted monitoring may ask the installed official gh CLI for its token using a bounded native process, with ambient token overrides removed. Only Rust receives that secret, in zeroizing owned buffers; no token is saved in the app vault/frontend/cache. Identity before/after private entitlement usage and a final exact-token reread reject switches. The official gh login/browser owns permissions and credentials; its normal grant can include broader scopes, disclosed by the provider consent and OpenToken's button/progress. No foreign OAuth client ID is copied. Disconnect does not log out gh, revoke its token or delete its credential-store entry. The advanced Plan-read personal billing adapter remains distinct.

Windows interactive login uses a fresh OS console without inherited redirected/null handles, fixed native executables/arguments and no command shell. Only the process handle created for this login can be terminated on cancellation. CLI waits are ten minutes for MFA; no automatic installer or model prompt is used. Antigravity/Devin/Muse now have native source paths described above; they are not imported browser sessions or a claim of live entitlement. See [the provider audit](PROVIDER-RESEARCH.md).

## App-owned API connections

Cursor Enterprise admin keys are privileged (`admin:*`), not read-only credentials; the UI warns before submission. The adapter only calls documented team-member and spending reads and binds the selected exact email/member ID to that key's scope. Copilot uses a fine-grained personal token with user Plan: read and binds the authenticated numeric GitHub ID before/after personal billing reads. Organization-paid usage and subscription allowance denominators are not inferred. Both adapters use fixed HTTPS destinations, disabled redirects, 2 MiB response bounds, bounded pagination and a 45-second whole-operation timeout. HTTP bodies/errors never reach diagnostics. Provider pause/burst/hourly verification limits also constrain reconnect attempts.

The Windows vault namespace is tied to this app's data directory and opaque connection ID; the app never enumerates credential entries. Connect/disconnect is serialized through the engine; failed settings persistence attempts secure-credential rollback and explicitly reports any rollback failure. Settings contain only identity/scope metadata, never submitted keys. Generic preference writes cannot alter secure connections. Submitted Rust key ownership and working read tokens use zeroizing wrappers, but there may be transient WebView/HTTP/OS copies; same-user memory access remains outside the security boundary. Fixed allowlisted provider-help URLs open in the external browser; arbitrary URLs are rejected. No foreign OAuth client IDs, password collection or browser-session extraction is used. Disclosed fixed private usage endpoints are used by the session adapters; the separately approved Muse key endpoint is credential-issuing, not read-only. See [setup and acceptance limits](CONNECTIONS.md).

## Local API

Binds IPv4 127.0.0.1 only, never 0.0.0.0. Read-only routes; no credential/refresh endpoints. Rejects Origin and Sec-Fetch-Site and requires loopback Host to prevent ordinary browser requests and DNS rebinding. These are browser barriers, not authentication of local software: any native process with access to your loopback interface can read usage, emails and paths. Disable the API if that is undesirable. No CORS allowance is emitted.

## Webview

Local assets only, strict CSP (no external scripts/network), explicit main-window capability, no shell/filesystem frontend plugin access. Directory selection is the sole dialog permission. All provider/network work happens in Rust. `?demo` never reads credentials and always shows a sample-data banner.

## Persistence and logs

Settings schema is validated; a corrupt primary falls back to a valid backup without silently overwriting either file. Removed connection grants are filtered from subsequent backups; `muse_device` grants are always excluded from automatic recovery. Writes use a same-directory unique temp file, flush/sync and rename. Unknown future settings versions fail closed. Usage files can contain emails and paths; they are private operational data, not encrypted secrets. Logs contain fault categories, not tokens or provider responses. Startup task arguments contain only --background, never encoded settings.

## Local history

Usage indexing opens CLI JSONL files read-only, only beneath configured/discovered homes' `sessions`, `archived_sessions` or `projects` directories. Symlink/reparse traversal, recursion, file counts, line allocations and per-pass bytes are bounded. Only usage metadata/counters are decoded; prompt/content/instruction fields are ignored and never persisted, transmitted or included in diagnostics. SQLite retains sanitized counters/cursors and credit observations, not transcripts or credentials. Its files inherit the user's data-directory ACLs and are not encrypted. Reference rates are bundled, not downloaded at runtime. See [usage tracking](USAGE.md) for financial limitations and retention.

## Live log identity boundary

Background tracking is enabled by default and can be disabled in Settings. Watchers cover only configured/discovered history subtrees, with bounded queues, disabled symlink following, changed-path validation and periodic reconciliation. Parsing remains read-only and off the UI thread. Hiding the dashboard does not stop Rust indexing. Notifications never become script/code and do not grant file-write or network privileges to the frontend.

A rate-limit snapshot in a session log normally has no signed-in identity. It must not be assigned to the current home owner based on timing or file metadata. Anonymous activity only schedules an existing authenticated provider read; the provider adapter still checks identity before/after. Provisional direct hints require explicit matching identity, current file-backed auth consistency, ready status, a recent/new timestamp, known matching reset windows and nondecreasing used quota. These are consistency/provenance gates, not cryptographic authenticity of local logs; same-user tampering is outside the boundary. Hints never clear failures, update credit history, renew tokens or claim billed spending. Historical counters remain provider-level.

Provider backoff and the running-instance read budget constrain activity-triggered checks. Watch failures fall back to periodic local scans, never to fabricated zero usage. Production does not expose the smoke test's WebView debugging port.

## Provider compatibility

OpenAI app-server experimental methods and Claude OAuth usage are undocumented/unstable interfaces. Provider access can change or be unavailable despite a successful build. Tests use synthetic credentials and fake transports; a green test run is not evidence of live subscription availability. No live Claude refresh is performed by the automated tests.

Report suspected credential leaks privately rather than attaching raw auth.json, .credentials.json, HTTP dumps or screenshots with account details to a public issue.
