# Architecture

**Current source-first migration:** [SOURCE-ARCHITECTURE.md](SOURCE-ARCHITECTURE.md) supersedes login-first setup below: metadata discovery, existing-session broker, separate local-history controls/readers, corroborated cache scopes and explicit-only recovery. All twelve provider types now have native reader paths with explicit mode/plan/profile limits, not twelve proven live entitlements. Muse's optional key-issuing mode is separately confirmed, never an implicit read-only fallback.

## Boundary map

```
React + TypeScript / WebView2
    │ narrow Tauri IPC commands, local window capability only
Tauri native shell ─ platform.rs (Task Scheduler COM, isolated CLI login)
    │ watches Rust snapshots; owns percentage icons and click placement
    ▼
Engine command channel ── single state owner ── watch<Snapshot>
    ▲                                  │              ├─ Axum read-only loopback API
    │                                  │              ├─ Tauri frontend state events
notify events / 60s safety / manual     │              └─ change-only atomic usage cache
                                       ▼
                       bounded (3) account reads
                         ├─ Codex adapter → app-server stdio / verified HTTP fallback
                         ├─ Claude adapter → OAuth usage + optional locked token renewal
                         ├─ Session/API service → Cursor, Copilot, Grok, regional keys/balances
                         └─ Local-provider readers → Devin CLI / owned Antigravity RPC / Muse MSP
                              └─ separately confirmed Muse key endpoint (credential-issuing)
```

Two Cargo crates keep compile boundaries useful without creating an enterprise-sized project for a tray utility:

- `opentoken-core`: pure `model` and `parser` modules; `storage`, provider adapters, command-driven `engine` and `api` orchestration. Core has no UI dependency.
- `opentoken`: Tauri composition root plus native platform/icon/logging adapters.
- `src/`: typed React view, a single IPC bridge, pure formatting/countdown functions. Frontend never reads credential files or contacts provider endpoints.

## State and identity

`AccountState` has explicit pending/ready/stale/faulted status, optional report and a typed FaultKind. Provider results are applied through `AccountState::apply`; ephemeral CLI quota hints have a separate fail-closed identity gate in `activity`. An identity-change, missing-login, expired-login or permission-revocation failure clears the report. Transient failures retain matching-identity observations as stale. Observation timestamps never advance on failure. API responses are snapshots, never fetch-on-request.

A Codex stable ID hashes workspace + normalized email (or user ID), not directory/name. File sources are checked again before and after reads. CLI before/after account checks include workspace identifiers when available. Ambiguous credential-store identities use a home-scoped fallback and are not merged by email alone. Claude API supplies no equivalent workspace identity here; Claude cards are conservatively keyed by config directory and labelled without an asserted email.

## Refresh pipeline

One bounded command channel owns state transitions; other consumers observe cloned immutable snapshots through Tokio watch channels. Refresh bursts coalesce, while settings and shutdown commands retain acknowledgements. Up to three account readers run simultaneously. HTTP clients are pooled across accounts, not created per account: CLI adapters share a client and official API connections share a second service-owned client, both with connection/request deadlines and redirects disabled.

File discovery is bounded to known roots, refuses directory symlinks during traversal, limits nested switcher depth and caps candidates at 256. Per-folder metadata stamps avoid re-decoding unchanged auth files. Credential-store probes have a 60s TTL; a probe's usage is consumed instead of immediately spawning a second CLI. Ordinary file-backed discovery does not spawn a CLI; the usage read does it once. Safety reconciliation covers missed watcher events. Exponential fault backoff has a 30-minute cap and deterministic jitter; explicit Retry-After can extend it (bounded to 32 days). Activity and manual refresh do not bypass server backoff. Credential-store discovery is gated by the same account schedule, with cached probes reused while blocked.

Views update by React account key; native icons regenerate only when rounded percentage/error/staleness changes. Countdown rendering makes no network calls. Cache writes happen only when account/folder data changes, not on each timer tick.

## Local usage and layout

`spending::{index,parse}` reads only bounded CLI-history subtrees. An engine-owned `Tracker` task exclusively owns the SQLite index and dispatches serial `spawn_blocking` passes. Native file notifications debounce/coalesce into changed-file imports; a bounded full reconciliation runs every minute. It operates while the flyout is hidden. `watch<TrackingState>` becomes a native `spending-changed` push event; frontend IPC is only a cached snapshot read with a two-minute safety fallback. `get_spending` remains a cached compatibility command, not a scan trigger. Parsing/index I/O never runs on the UI thread or calls a provider itself. Fresh metadata activity sends a separate engine command; `schedule` advances identity-checked quota reads with a 60-second automatic spacing, a rolling 60-cycle/hour per-identity budget for this running instance, and server backoff. Active cadence lasts ten minutes after activity, then returns to the selected idle interval. Known reset deadlines also schedule confirmation, never fabricate a replenished percentage. Anonymous logs cannot change an identity's percentage. Explicit matching identity, current file-auth checks, ready status, fresh timestamps and unchanged reset windows are required for provisional `cli_log` reports; a budgeted provider read confirms them. Counters, cursor state and verified credit observations are stored separately from the quota snapshot. Pricing is bundled data plus validated user overrides; no runtime pricing network dependency. See [usage tracking](USAGE.md) for deduplication, bounds and coverage.

`accountOrder` is a presentation preference keyed by stable identity. Pointer/keyboard sensors activate only on the six-dot button. A dedicated channel command merges order into the latest engine-owned settings, persists before acknowledging, and does not force usage reads. The frontend optimistically reorders and rolls back on failure, preserving unrelated saved/unsaved settings. Cards retain their disclosure state by React key; order never changes credentials, identity deduplication or Windows tray placement.

## Windows lifetime

Tauri single-instance plugin provides platform IPC and duplicate-instance forwarding. The window hides on explicit close/collapse; native deactivation also hides it only when unpinned. Pinning defaults off in Rust settings, frontend state and the hidden native window config. An explicit saved pin survives restarts and focus changes; missing preferences start unpinned. A generation-guarded 120 ms dismissal policy distinguishes real external focus from internal controls/owned popups, protects the native folder picker with an RAII hold, and coordinates tray gestures with a bounded lease. General settings placement does not steal focus or reopen a dismissed panel. Intentional Exit shuts down with code 0. The transparent WebView sits over actual Windows DWM acrylic with native rounded-corner clipping. Placement is bottom-right by default and clamps to the monitor work area (not full screen); bottom-right and clicked-icon placement are configurable. Each account owns a single Fluent percentage badge by default, with an optional provider-logo/percentage-icon pair. Badges use a 64px antialiased arc and the installed Windows UI font, rendered through scoped GDI resources; font files are never bundled. Style changes reconcile tray resources on the UI thread immediately, using the latest engine snapshot. Windows controls icon order, spacing and overflow; the app never injects widgets into Explorer. Removed tray slots are explicitly unregistered from Tauri's resource table, since dropping only the application handle does not remove Tauri-owned icons. Fatal panics exit nonzero so Windows can restart a scheduled instance. The native tray library re-registers on TaskbarCreated. A separate 15-second main-thread health pass verifies shell updates, not just cached handles. Failed registrations are retried with capped spacing through that same library path on the app-owned icon HWND; glyph cache keys advance only after successful updates. The same icon identity is retained, and healthy/overflow icons are not reordered or periodically recreated. Diagnostics distinguish unconfirmed registrations from cached resource counts. Explicit --no-startup processes with an absolute isolated data override receive a path-scoped single-instance identity so native tests cannot close/forward into the live default instance. Log writing happens on a dedicated buffered writer with 2 MB × 3 rotation.

`motion.rs` owns flyout transitions independently of focus-dismissal epochs. Native UI-thread frames roll the actual glass HWND out of its dock (300 ms open, 220 ms close), interpolating its top/height and uniform alpha. A short-lived blocking worker waits on `DwmFlush` off the UI thread, with a bounded fallback if composition is unavailable/returns immediately. It submits one acknowledged UI frame at a time, sampling progress when that callback actually executes, then exits at completion/cancellation. No coarse post-frame sleep, raw native timer/property callbacks, global timer-resolution changes or idle polling are used. Responsive ease-out (no flat-start dead zone), distance-aware reversals and skipped redundant HWND/alpha/controller-bound writes reduce visible jumps. A `WM_STYLECHANGING` guard preserves only the active `WS_EX_LAYERED` lease through Tao show/pin style rebuilds, preventing a transparent first frame from becoming opaque; all other style bits remain caller-owned. The dock-side edge is fixed, without a second positional nudge. Bounded native callback timestamps support local diagnostics, not a claimed GPU presentation trace. A temporary subclass of only the owned main HWND prevents intermediate `WM_SIZE` from resizing/reflowing WebView2; it is removed and normal sizing resynchronized after restoring the full host. The native viewport remains its original size; no CSS content transform or stationary backdrop is used. Direct controller bounds are used where needed, not Wry's main/non-child `set_position`, which changes the host itself. Reversals reuse current geometry/opacity; generation checks reject stale frame/finish callbacks. Full host dimensions are cached during motion so reversal/placement never uses a partially collapsed size. Dock coordinates, host/viewport size, layered-window state, acrylic and corners are restored at completion. General preference saves acknowledge only after their native style/tray/placement changes are applied. The frontend's `dashboard_ready` handshake avoids revealing empty content; a 1.5-second fallback prevents readiness failure from permanently suppressing the window. Tray toggles latch presented visibility, including Closing/Opening/Waiting, on an icon-matched press; an in-flight blur-close must not be mistaken for an already-closed panel. Windows DoubleClick begins the second press, which lacks a normal Down. Only a matching nonexpired Up consumes that gesture once; there is no release-only reopen fallback. Explicit Show/CLI actions can still reverse a close. A read-only native gesture flag supports regression inspection. Windows accessibility animation preferences are queried without writes; reduced-motion/remote sessions bypass transitions. Owned-popup/modal focus is never reclaimed by completion. Motion does not touch engine settings or quota scheduling.

Scheduled startup is a single COM-registered interactive, limited task, with a logon trigger and failure restarts. It is not a process-hang detector, does not supervise manually launched instances, and is never touched in development/--no-startup runs.

## Native personal Cursor connection

`connections::cursor_personal` is an original Rust desktop-session adapter behind a targeted `CursorPersonal` engine command. It verifies explicit consent before bounded `spawn_blocking` SQLite access and uses fixed-host private dashboard requests through the existing redirect-disabled/bounded HTTP service. The browser never receives a Cursor token. New `Connection.mode` defaults to `api`; `cursor_app` adds only the bound profile path and public verified identity. Personal mode never touches Credential Manager, copies the database, refreshes tokens or modifies Cursor files. General connection/settings serialization, canonical-save acknowledgements and snapshot/tray cleanup remain shared with existing API connections.

A native database notification becomes `CursorChanged`; the service fingerprints just the authentication row. Changes clear old readings and advance budget-preserving verification, never server-throttle bypass. Unchanged usable tokens do not trigger extra quota reads; transient unreadable watcher samples alone do not prove an account switch. Minute reconciliation is the fallback. A personal reconnect explicitly replaces the previous account for the same normalized profile scope while preserving Enterprise entries. `cursor_dashboard` report provenance propagates to panel/details/stripe/tray; raw quota percentages remain used, UI remains left, missing fields are not filled by team pools or estimates. Desktop sign-in launch checks fixed standard executable paths and requires no shell/installer or new runtime. This is distinct from the potential CLI/browser-import routes researched in [CURSOR-RESEARCH.md](CURSOR-RESEARCH.md).

## Automatic CLI account setup

`cli_profiles.rs` manages private per-provider pending profile metadata and opaque new CLI homes without copying credentials. Absolute unlinked-directory validation, bounded pending/auth metadata, a 100-profile bound, pending reuse and commit-after-verification keep storage predictable. Official CLIs own authentication writes; the coordinator reads only metadata/child status before requesting a targeted engine verification. `CliConnect` verifies through the existing adapters, serializes persistence against latest settings, records a normal read schedule and publishes only after success. Default existing homes are retained when an implicit list becomes explicit. `CliDisconnect` excludes identity sources but does not delete credentials; Claude discovery now honors the same exclusions. Generic preference writes preserve newly connected managed homes.

`src-tauri/src/cli_sign_in.rs` hosts the shared epoch/revision-guarded state machine separately for Codex and Claude. It launches native executables directly with fixed official subscription-login arguments and isolated home environments, clears API-token/endpoint overrides, never captures login output, and kills only its owned child on cancelled/expired waiting. Engine verification is non-cancellable once handed off. Public status and targeted account-settings events let the root view update across navigation while preserving drafts. No arbitrary path or CLI command is accepted by these sign-in IPC routes. The former arbitrary-home `login_codex` command is removed; the guarded native folder picker remains only as a compatibility/native-regression command, with no UI entry point.

## Single-action Cursor sign-in

`cursor_login.rs` is a platform-independent native state machine hosted by `src-tauri/src/cursor_sign_in.rs`. An explicit action starts at most one run; local marker probes are private engine commands, not frontend token reads. A ready session is verified immediately. Missing/rejected sessions cause one Cursor launch and a bounded background wait; unchanged rejected credentials are not repeatedly submitted. Epoch/revision checks suppress stale work, checking/waiting is cancellable, and a verification already handed to the engine is allowed to finish. Disconnect and exit reset progress. No idle polling task runs before a user starts sign-in.

`useCursorLogin` subscribes before reading cached progress and guards revisions. Native settings observation emits connection metadata independently of component lifetime; the root view merges only that list and refreshes cached snapshots, preserving unsaved preferences even after navigation. Default personal UI is one inline button plus caption/info; Enterprise fields are hidden behind a text toggle, and connected scope explanations are collapsed. Preview flows remain synthetic and never launch Cursor/read credentials.

## Expanded provider adapters and Windows login ownership

`reported.rs` contains original, fixed-host Z.ai/Kimi Code/OpenCode Go quota and DeepSeek balance adapters, sharing `Service` verification gates, response bounds, secure-store rollback and scheduling. Region plus hashed key scope binds caches without inventing a human identity/email. Provider models/API filtering/tray artwork/frontend capability gates now include all four. Missing quota/balance fields fail closed; balance-only data never supplies a percentage or local-history estimate.

`github_personal.rs` adds a distinct `github_cli` connection mode: opt-in bounded official `gh auth token` reads, `/user` identity around the unofficial Copilot entitlement endpoint, final local-token comparison and metadata-only persistence/disconnect. `github_sign_in.rs` hosts the normal native coordinator and delegates login to gh's own registered application; no borrowed VS Code client ID or browser import. `copilot_internal` provenance is separate from advanced official personal billing. Credentials stay owned by GitHub CLI, not copied to OpenToken's vault.

`grok_personal.rs` adds `grok_cli` monitoring through the known official CLI profile, xAI OIDC userinfo around private CLI credit billing and final exact-token comparison. It never renews the CLI token or copies it to the vault. `grok_sign_in.rs` delegates interactive login to the installed official client with a ten-minute coordinator window; cached status performs no credential access. `grok_cli` report provenance, monitoring-only disconnect, background scheduling and API/tray/UI support are separate from recorded local token history. Team/missing quotas are not assigned a personal allowance.

`login_process.rs` uses Windows CreateProcessW with no inherited standard handles and a new console. The old release's login child had three nonterminal streams; the dedicated before/after probe now asserts usable input/output/error handles. Fixed provider arguments, scoped home environment, stripped credential/nested-session overrides and owned-handle cleanup preserve native user control. CLI/GitHub MFA waits are ten minutes; Cursor's existing app wait remains two minutes. Broader provider findings and unimplemented paths are in [PROVIDER-RESEARCH.md](PROVIDER-RESEARCH.md).

## Antigravity, Devin and Muse local-provider service

`connections::local_providers` contains original typed readers, with native Windows ownership helpers and a bounded Muse MSP transport. `DevinCli`/`DevinApp`, `AntigravityApp`/`AntigravityCli` and `MuseCli` connections preserve profile/credential-or-authenticated-user scope without copying credentials. Default existing-source connection never launches login. Antigravity uses native process/WMI/SID/session/lifetime/TCP evidence, exact CSRF and identity checks around fixed loopback RPC, plus explicit shared-bucket parsing. Only its isolated loopback client permits self-signed certificates and it never uses proxies/redirects. Devin pins the private HTTPS server, reads the CLI TOML or the bounded read-only desktop authentication record, checks deployment context before/after and distinguishes raw ambiguous fields from meterable percentages. Antigravity tests both desktop profiles and has a separate exact-entry valid-token-only CLI reader using daily Cloud Code, not production-Gemini pool substitution. `source_db.rs` supplies bounded exact-key SQLite reads without database copies. An explicit consent-gated native diagnostic path returns only source/counts/faults before startup/UI/logging and never persists monitoring. Real installed-client findings are in [COMPATIBILITY-2026-10-19.md](COMPATIBILITY-2026-10-19.md). No borrowed OAuth client or fabricated IDE version is used.

The existing-source engine handle owns one cancellable run/provider outside the serialized command queue, allowing cancellation while the reader is waiting. Duplicate starts cannot launch another probe. Both normal/drained paths reconcile canonical settings and register watchers. File watch registration precedes scope confirmation so an immediate credential change cannot slip through the read/watch gap. Changed Devin/Muse credentials invalidate prior reports without bypassing network budgets. Muse MSP preserves provider observation time and expires windows natively rather than inventing resets/full allowance.

`MuseDevice` is a different, non-read-only mode. Only the separate native IPC path with a default-No, owned Windows confirmation can enable it in the app. Saved mode authorizes bounded scheduled Meta key-endpoint requests; no prompt, payment operation, returned-key use/storage or CLI-file write occurs. The service requires authenticated email and actual quota and discards private response strings/buffers where owned. Source/cache/UI/tray labels distinguish this from MSP. Provider-side effects cannot be undone by cancellation or a failed save. Automatic settings backups omit the credential-issuing mode so recovery cannot silently re-enable it after removal. The primary retains deliberately approved monitoring across normal restarts. Inline CLI login support, empty MSP/idle API responses, custom installs/multiple Antigravity servers and live entitlements remain explicit limitations. [CONNECTIONS.md](CONNECTIONS.md) and [REMAINING-PROVIDERS.md](REMAINING-PROVIDERS.md) specify the contract.

## Official API connections

`connections.rs` adds typed, fixed-host Cursor Enterprise and personal Copilot billing adapters. `Service` owns request bounds, identity checks, per-provider connection/pause gates and persistence transactions through an injected `CredentialStore`. API-key production connections use the native Windows Credential Manager adapter in `src-tauri/src/credentials.rs`; tests inject an isolated memory store and private loopback HTTP fixtures. No endpoint override is exposed through settings, IPC or environment variables. API connection settings default empty and carry only public identity/scope metadata. Targeted `Connect`/`Disconnect` engine commands merge with the latest preferences, verify before secure writes, restore credentials after failed settings persistence, update snapshots and reuse the normal scheduled readers. General Settings commands preserve the engine-owned connection list. Removing all connectors is a valid empty configuration.

The frontend separates live capability (`isTrackedProvider`) from local-token-history capability (`isHistoryProvider`). Cursor's official spending/budget fields and Copilot's request/AI-credit billing values never feed the Codex/Claude local token donut, credit observer or cost estimates. API-backed accounts have no invented credential-folder sources. Provider names/icons, API filtering and native tray resources cover the new variants; missing quota denominators remain unavailable. Connection forms hold keys ephemerally, clear them on submission and preserve unrelated settings drafts. [Connection documentation](CONNECTIONS.md) records the official sources and live-acceptance boundary.

## Intentional non-goals

No Electron/Node backend, .NET compatibility layer, custom HTTP parser, supervisor process, persistent Codex helper pool, cloud service, automatic credential copying, full-drive account search, telemetry, auto-update, SSE transport or write-capable local HTTP API. Provider additions require a new typed adapter and engine dispatch, not a dynamic runtime plugin loader.
